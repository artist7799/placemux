# PlaceMux — Technical Interview Preparation Guide

This guide contains **35 technical interview questions and answers** based on the actual design, codebase, and implementation of **PlaceMux**.

---

## 📱 1. React & Frontend Architecture

### Q1: How is global authentication state managed in the PlaceMux React frontend?
**Answer**: Authentication state is managed using React Context (`AuthContext.tsx`). The provider initializes state from `localStorage` tokens and user metadata. It exposes helper functions `login`, `register`, and `logout` alongside state flags `isAuthenticated`, `isLoading`, and `user`. An Axios interceptor automatically attaches the JWT Bearer access token to outgoing HTTP request headers.

### Q2: How are protected routes and role authorization handled in React Router?
**Answer**: Route protection is enforced using a generic `<ProtectedRoute>` wrapper component in `App.tsx`. It inspects `isAuthenticated` and `user.role`. If the user is unauthenticated, it redirects to `/login`. If the user's role is not included in the `allowedRoles` array (e.g. a student trying to access `/admin/dashboard`), it redirects to `/unauthorized`.

### Q3: How does the frontend handle API loading, empty, and error states gracefully?
**Answer**: Dashboard components maintain explicit local state variables `[loading, setLoading]` and `[error, setError]`. During asynchronous Axios fetches, `loading` renders clean glassmorphic skeletal fallback loaders. Empty array responses render contextual empty state cards (e.g., "No active placement drives found"), while API failures trigger toast notifications and error messages without breaking the UI layout.

## 🟦 2. TypeScript & Type Safety

### Q4: How is type safety maintained across the monorepo from database to frontend?
**Answer**: Database model types are automatically generated by Prisma CLI (`@prisma/client`), producing TypeScript interfaces for all 25 schema entities. Express request body payloads are validated using Zod schemas (`auth.validator.ts`, `college.validator.ts`, `admin.validator.ts`), producing inferred TypeScript types (`z.infer<typeof schema>`) that guarantee runtime payload validation.

### Q5: What custom TypeScript interface extensions were created for Express requests?
**Answer**: A custom `AuthenticatedRequest` interface extending `express.Request` was defined in `auth.ts`:
```typescript
export interface AuthenticatedRequest extends Request {
  user?: {
    userId: string;
    email: string;
    role: Role;
  };
}
```
This allows route controllers to access `req.user` with full autocompletion without using unsafe `any` assertions.

## 🟢 3. Node.js & Express REST API Server

### Q6: How is global error handling structured in the Express backend?
**Answer**: A centralized error middleware (`middleware/error.ts`) intercepts errors passed to `next(err)`. It formats standard JSON responses:
```json
{
  "success": false,
  "message": "Error description",
  "error": "Details"
}
```
In production mode (`NODE_ENV=production`), detailed stack traces are hidden to prevent information disclosure.

### Q7: How does the Node.js backend communicate with the Python FastAPI AI microservice?
**Answer**: The backend uses an integration service `AIService` (`services/ai.service.ts`) backed by `axios`. The Axios instance configures a 5000ms timeout. If the AI service fails or times out, `AIService` catches the error and invokes a fallback calculation engine, returning valid baseline metrics so user requests do not fail.

## 🐘 4. PostgreSQL & Prisma ORM

### Q8: How are cascade deletion rules configured in Prisma schema?
**Answer**: Foreign key relations use `@relation(onDelete: Cascade)` or `@relation(onDelete: SetNull)`. For example, deleting a `User` automatically cascades to delete their associated `Student`, `Company`, `College`, or `RefreshToken` records. Deleting a `Student` cascades to clean up `Education`, `StudentSkill`, `Project`, `Certification`, `Resume`, and `Application` rows.

### Q9: Why was `Prisma.groupBy` used in the Admin and College analytics engines?
**Answer**: `prisma.application.groupBy` and `prisma.student.groupBy` execute single native SQL `GROUP BY` aggregate queries on PostgreSQL instead of loading thousands of rows into Node.js memory. This returns exact count statistics grouped by `currentStatus` or `branch` in milliseconds.

## 🔒 5. JWT, Security & Anti-Cheat

### Q10: How does token authentication and rotation work in PlaceMux?
**Answer**: PlaceMux implements a dual-token strategy:
- **Access Token**: Short-lived JWT (15 minutes) signed with `JWT_SECRET`, sent in the `Authorization: Bearer <token>` header.
- **Refresh Token**: Long-lived JWT (7 days) signed with `REFRESH_TOKEN_SECRET`, stored in PostgreSQL `RefreshToken` table and supplied via `/api/auth/refresh` to issue new access tokens upon expiration.

### Q11: How does the online assessment system prevent cheating via browser inspection?
**Answer**: When a student requests an assigned assessment, the controller strips `correctAnswer` from every `Question` model before building the `AssessmentSession` payload. The correct answer key exists only on the backend database and is evaluated solely when answers are submitted.

### Q12: How are HTTP security headers and rate limits enforced?
**Answer**: `helmet()` middleware sets standard security headers (`X-Frame-Options: SAMEORIGIN`, `X-Content-Type-Options: nosniff`, `X-XSS-Protection`). `express-rate-limit` caps client IP requests to 300 requests per 15-minute window.

## 🏢 6. Multi-Tenancy & RBAC

### Q13: How is multi-tenant college data isolation enforced in backend endpoints?
**Answer**: College controllers fetch the `College` entity associated with `req.user!.userId`. When retrieving student directories or placement drives, queries explicitly include `{ where: { OR: [{ collegeId: college.id }, { collegeId: null }] } }`. In student verification endpoints (`verifyStudent`), the service verifies `student.collegeId === college.id` before executing updates, throwing `403 Forbidden` for unauthorized cross-college modifications.

### Q14: How does `authorize(...allowedRoles)` middleware restrict route access?
**Answer**: The `authorize` higher-order middleware accepts allowed roles:
```typescript
export const authorize = (...roles: Role[]) => {
  return (req: AuthenticatedRequest, res: Response, next: NextFunction) => {
    if (!req.user || !roles.includes(req.user.role)) {
      return res.status(403).json({ success: false, message: 'Forbidden' });
    }
    next();
  };
};
```

## 🐍 7. Python FastAPI & AI Microservice

### Q15: Why was Python FastAPI selected for the AI Microservice instead of performing NLP in Node.js?
**Answer**: Python provides mature machine learning and natural language processing libraries (`scikit-learn`, `numpy`, `pypdf`). FastAPI provides high-performance asynchronous API execution with automatic Pydantic input validation and OpenAPI documentation (`/docs`).

### Q16: How does PyPDF extract text from candidate resume uploads?
**Answer**: `ResumeAnalyzerService.extract_text_from_pdf_bytes` accepts raw file bytes from FastAPI `UploadFile`, initializes `pypdf.PdfReader`, iterates through all pages, extracts plain text content, and concatenates it for regex skill parsing.

## 🤖 8. NLP, TF-IDF & Cosine Similarity

### Q17: How does the TF-IDF Cosine Similarity algorithm calculate candidate-job match percentage?
**Answer**: `TfidfVectorizer` transforms candidate profile text (skills, branch, resume text) and job description text into TF-IDF term-frequency vectors. `cosine_similarity(vec1, vec2)` calculates the dot product divided by the product of their L2 norms, yielding a normalized similarity score between 0.0 and 1.0.

### Q18: How is the composite match percentage calculated?
**Answer**: The match calculation combines three weighted components:
1. **Jaccard Skill Overlap Ratio** (55%): Intersection of candidate skills vs required skills.
2. **TF-IDF Text Similarity** (30%): Cosine similarity of vectorized candidate text and job description.
3. **Academic Eligibility** (15%): Boolean check verifying student CGPA $\ge$ job `minCgpa` and student branch $\in$ `eligibleBranches`.

### Q19: Why does PlaceMux include an Ethical AI disclaimer in response payloads?
**Answer**: To comply with ethical AI standards, every match API payload includes a mandatory disclaimer stating that match percentages are decision support indicators for self-assessment and **must not be used for automated hiring decisions**.

## 🐳 9. Docker & Nginx Infrastructure

### Q20: How are multi-stage Docker builds optimized for Node.js and React?
**Answer**: 
- **Backend Dockerfile**: Stage 1 installs devDependencies and compiles TypeScript (`tsc`). Stage 2 copies only compiled `dist/` and pruned production `node_modules/`, keeping the final runner container lightweight.
- **Frontend Dockerfile**: Stage 1 builds Vite static assets. Stage 2 copies built HTML/CSS/JS into an `nginx:alpine` image.

### Q21: How does Nginx route traffic in production?
**Answer**: Nginx listens on port 80. Client static single-page app routes (`/`) fall back to `index.html` via `try_files $uri $uri/ /index.html`. API calls matching `/api/` are reverse-proxied to `http://backend:5000/api/`.

## 📊 10. Database Schema & Application Pipelines

### Q22: How are application status transitions audited?
**Answer**: Whenever an application status is updated (e.g. from `APPLIED` to `SHORTLISTED`), a new row is appended to `ApplicationStatusHistory` capturing `applicationId`, `status`, `changedBy` (userId), and `remarks`.

### Q23: What happens in the database when a student accepts a job offer?
**Answer**: When `PATCH /api/offers/:id/respond` receives status `ACCEPTED`, the service updates `Offer.status = ACCEPTED` and automatically mutates `Student.placementStatus = PLACED` within a database transaction context.

## 🧪 11. Testing & Code Quality

### Q24: How are integration tests structured in Jest?
**Answer**: Tests use `supertest` to execute HTTP requests against the Express `app` instance without spawning a live network listener. JWT access tokens for test roles are generated using `generateAccessToken({ role })`.

### Q25: How are Python AI service endpoints tested?
**Answer**: Pytest tests use `httpx.AsyncClient` with `httpx.ASGITransport(app=app)`. This executes FastAPI requests asynchronously in memory without launching an actual Uvicorn server process.

## 🔐 12. Security & Compliance

### Q26: How does Prisma protect against SQL Injection?
**Answer**: Prisma ORM uses parameterized queries for all database operations. User input is never concatenated into raw SQL strings.

### Q27: How are administrative audit logs implemented?
**Answer**: `AdminService.logAdminAction` inserts records into the `AuditLog` table, capturing `userId`, `action`, `ipAddress`, and a JSON `details` payload describing previous and updated states.

### Q28: How is sensitive data prevented from leaking in error responses?
**Answer**: The central error handler sanitizes runtime errors. Stack traces are omitted in non-development environments, and standard HTTP status codes (`400`, `401`, `403`, `404`, `422`, `500`) are consistently returned.

## 🚀 13. System Performance & Optimization

### Q29: How are database queries optimized for large student rosters?
**Answer**: Indexes are defined on high-frequency lookups (`userId`, `collegeId`, `email`, `code`). Queries use Prisma field selection (`select: { id: true, name: true }`) to fetch only required attributes.

### Q30: How does Vite optimize frontend bundle sizes?
**Answer**: Vite leverages Rollup code-splitting, tree-shaking, and CSS minification. Production build static assets are gzipped by Nginx before serving to clients.

## 🔮 14. Architecture & Design Trade-offs

### Q31: What are the trade-offs of using a monorepo structure?
**Answer**: 
- *Pros*: Shared TypeScript definitions, centralized Docker orchestration, single git repository, simplified CI pipelines.
- *Cons*: Larger git repository size, requires clear package boundaries between subdirectories.

### Q32: Why use JWT instead of session cookies for backend auth?
**Answer**: JWTs are stateless, horizontally scalable across multiple API container replicas, and eliminate the need for server-side session storage databases.

### Q33: How does the application handle database migrations?
**Answer**: Prisma handles schema migrations via declarative schema definition in `prisma/schema.prisma`. In production, `npx prisma migrate deploy` applies pending SQL migrations.

### Q34: What is the purpose of the `/health` endpoints in backend and AI service?
**Answer**: Health check endpoints return simple JSON status payloads. Docker Compose and load balancers poll these endpoints every 30 seconds to monitor container health and restart failing services automatically.

### Q35: How would PlaceMux scale to support 100,000 active students?
**Answer**: 
1. Move PostgreSQL database to a managed cluster (AWS RDS / GCP Cloud SQL) with read replicas.
2. Store candidate PDF uploads in S3/GCS buckets instead of local storage.
3. Scale Node.js backend and Python AI microservice container instances behind an Nginx load balancer.
